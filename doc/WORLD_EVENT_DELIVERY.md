## 문서의 목적

현재 월드 이벤트 전달 방식의 차이와 개선안을 정리한다. 통일 작업 이후에는 새 기능의 주변 브로드캐스트를 구현·리뷰할 때 따르는 가이드로 사용한다. 공통 규칙이 바뀌면 문서도 함께 갱신한다.

§2는 현행 코드의 조사 결과다. §1과 §3~7은 적용할 설계이며, §6은 새 기능 구현 절차, §8은 구현 시 검증 항목이다.

## 1. 공통 원칙과 범위

1. 주변 월드 상태의 전달 반경은 `EVENT_DELIVERY_RADIUS = 32 m` 하나로 통일한다. 웹과 agent-client에 같은 규칙을 적용한다.
2. 대상의 위치·형상·공간으로 수신자를 결정한다. 플레이어·몬스터 이동은 시작점 또는 목표점 중 하나라도 반경 안이면 전달한다.
3. 서버는 연결별로 전달한 대상 목록을 관리한다. 이를 관심 집합(AOI, Area of Interest)이라 부른다. 진입 시 최신 상태, 체류 중 변경, 이탈·삭제 시 정리를 전달한다.
4. 클라이언트의 활성 상태와 보관용 캐시를 구분한다. 재진입 시 서버의 최신 상태를 확인한다.
5. agent-client는 활성 관심 집합을 LLM 인지에도 사용한다. 별도 27 m 거리 필터와 `NPC_SIGHT_RADIUS`는 제거한다.

### 화면 가장자리 정책

32 m는 시야 범위와 네트워크 대역폭·서버 처리량 사이의 절충값이다. 넓은 화면 가장자리에서 구독 범위 밖의 변경을 받지 못하거나, 접근할 때 오브젝트·상호작용이 갑자기 나타나거나 사라지는 현상은 허용한다. 화면비·해상도별 반경 확대나 화면 전체 동기화는 요구하지 않는다.

동기화 보장은 공통 판정으로 구독하는 대상에 적용한다. 구독 중 변경 전달, 이탈 정리, 재진입 시 최신 상태 복원은 유지한다.

### 메시지 분류

| 분류 | 예 | 전달 원칙 |
| --- | --- | --- |
| 주변의 지속 상태 | 플레이어·몬스터·집·문·아이템·영지 창고·울타리·좌판·음식·모닥불·연주·낚시 | 공통 반경과 진입·변경·퇴장 처리 |
| 주변의 일회성 효과 | 공격·피격·강화 효과, 채팅 말풍선, 음표 | 효과 대상의 공통 반경. 재진입 시 과거 효과 재생 안 함 |
| 변경 가능한 지형 | 건축·조경으로 바뀌는 높이·나무·풀·조경 타일 | 해당 타일 구독자에게 갱신 |
| 정적 배치 | 편집기로 놓은 일반 가구·오브젝트 | HTTP 지역 로드·캐시 유지 |
| 개인·참여자 정보 | 명령 결과·위치 보정·인벤토리·경험치·창고 내용물·거래·귓속말·파티 상태 | 참여자·권한 기준 직접 전달 |
| 전역 서비스 | 시간·날씨·서버 공지·공개 월드 지도 | 서비스별 범위와 버전 정책 |

한 행동에 개인 결과와 주변 표현이 함께 있으면 각각 전달한다. 예를 들어 창고 배치 결과와 인벤토리는 조작자에게, 창고 외형은 구독자에게 보낸다. 몬스터 AI의 `MonsterAssigned`와 소유권 해제는 제어 메시지이며, 반경 밖의 이전 소유자에게도 해제가 도달해야 한다.

공격 사거리, 상호작용 거리, 몬스터 감지·추격 거리, 음량 감쇠, GPU 렌더링 거리는 각 기능의 규칙으로 유지한다. 차단 사용자 필터도 유지한다.

### 정적 배치의 운영 전제

프로덕션에서는 편집기로 일반 가구·오브젝트를 변경하지 않는다. 이 데이터는 배포 사이에 고정된 것으로 취급한다.

- 기존 1024 m HTTP 지역 파일과 지역 캐시를 유지하며, `put_object`에 실시간 전파를 추가하지 않는다.
- 배포 데이터가 바뀌면 웹·agent-client의 캐시, 다운로드 기록, 충돌 데이터를 함께 갱신한다.
- 플레이어가 배치·회수하는 영지 창고·울타리·좌판과 건축·철거하는 집은 동적 대상이다. 정적 의자에 앉는 동작도 플레이어 상태로 전달한다.

## 3. 수신자 판정

### 3.1 반경과 형상

```rust
pub const EVENT_DELIVERY_RADIUS: f32 = 32.0;
```

[shared/src/world.rs](../shared/src/world.rs)에 정의한다. 서버·agent-client는 shared를 사용하고, 웹은 공통 `world_constants()` WASM API로 읽는다. 기존 `dungeon_constants()`의 노출 경로도 이 API로 옮긴다.

`R = EVENT_DELIVERY_RADIUS`일 때 기본 판정은 다음과 같다.

```text
구독 대상 = 공간이 호환됨(viewer, subject)
            AND XZ_최단거리(viewer.position, subject.bounds) <= R
```

- 관찰자 위치는 서버가 확정한 캐릭터 위치다.
- 점은 중심, 선분·영역은 실제 형상까지의 최단거리로 판정하며 경계 R을 포함한다.
- X축 월드 순환을 적용한다. 점에는 `Position::dist_xz_sq`를 사용하고 선분·영역도 같은 규칙을 따른다.
- 공간 인덱스의 사각 경계는 후보 조회용이다. 여러 방 사이 빈 공간 등을 실제 형상으로 간주하지 않는다.
- 반경 제곱과 조회할 셀 범위는 R에서 계산한다. 저장 청크·인덱스 셀 크기는 최종 구독 판정에 영향을 주지 않는다.

### 3.2 층과 공간

| 대상 | 공간 조건 |
| --- | --- |
| 플레이어·몬스터·아이템·영지 창고·음식·좌판 등 | 같은 층. 지하는 던전 식별자와 깊이도 일치 |
| 집 전체·문·창문 | 집을 구독하는 지상 및 주택층 사용자. 지하 던전 제외 |
| 울타리 | 지상층 |
| 던전 입구 / 내부 문·소품 | 입구는 지상 구조, 내부는 같은 던전·깊이 |
| 지표의 높이·나무·풀·조경 | 지상 및 주택층에서 사용하는 지표 데이터. 지하 경로의 입구 구조는 별도 대상으로 표현 |

계단은 서버가 확정한 공간 전환 시점에 판정한다. 집 외관 구독으로 다른 층의 플레이어·몬스터까지 공개하지 않는다.

### 3.3 집·문·창문

집은 모든 층의 방·문·창문을 포함하는 한 동기화 단위다. 집의 실제 바닥 영역까지 거리가 R 이내면 전체 스냅샷을 받고, 구독 중에는 모든 문·창문 변경을 받는다. 집 안의 관찰자는 거리가 0이다. 반대쪽 문이 R 밖이어도 집 구독자에게 변경을 전달한다.

집 전체가 범위를 벗어나면 활성 데이터·표시·충돌을 해제한다. 64 m 청크는 서버 저장·검색에만 사용하며, 일반 플레이의 집 청크 로드·거리별 보관 정책은 제거한다.

2층(`floor_level=1`) 창문을 열면 해당 집을 구독하는 지상(`floor_level=0`)과 다른 주택층 사용자도 변경을 받는다. 직접 조작할 때의 층·근거리 검사는 별도로 유지한다. 웹은 숨긴 상층 메시의 상태도 갱신해 다시 표시할 때 반영한다.

### 3.4 플레이어·몬스터 이동

각 끝점의 공간 조건과 거리를 따로 검사하고, 수신자 합집합에서 중복을 제거한다.

```text
시작점_근처 = 공간이 호환됨(viewer, from.space)
              AND 거리_XZ(viewer.position, from.position) <= R
목표점_근처 = 공간이 호환됨(viewer, to.space)
              AND 거리_XZ(viewer.position, to.position) <= R
이동_전달 = 시작점_근처 OR 목표점_근처
```

| 메시지 | 판정할 구간 |
| --- | --- |
| `PlayerMoved` | 서버의 직전 확정 위치 → 패킷의 새 `position` |
| `MonsterMoved` | 패킷의 `position` → `target_position` |
| 앞으로 이동 의도를 전달하는 경우 | 현재 위치 → 서버가 승인한 현재 구간 목표 |

목표점은 해당 패킷의 이동 구간 끝점이다. 장거리 최종 목적지나 미시작 경유지는 포함하지 않는다. 순간이동은 양 끝의 공간에 알리고 중간을 걷는 애니메이션으로 재생하지 않는다.

두 끝점이 모두 R 밖이면 선분 중간이 반경을 통과해도 이 조건에는 포함되지 않는다. 그런 이동까지 한 패킷으로 지원하려면 선분 교차 판정이 필요하다.

### 3.5 던전 문·소품

문은 개구부 중앙, 소품은 배치물 중심의 월드 좌표를 사용한다. 문 회전이나 조작자 위치에 따라 기준점을 바꾸지 않는다. 입구 마커와 실제 문 좌표가 다르면 실제 문 좌표를 사용하며, 서버·웹·agent-client가 같은 레이아웃으로 계산한다.

수동 토글·자동 닫힘·소품 파괴와 진입 스냅샷에 같은 판정을 적용한다. 정적 던전 레이아웃 캐시와 동적 문·소품 구독을 분리한다.

### 3.6 조경·지형 타일

타일의 실제 영역까지 최단거리에 R을 적용한다. 예를 들어 64×64 m 타일 중심에서 한 축 방향으로 60 m 떨어진 관찰자는 가장자리와 28 m 거리이므로 구독 대상이다. 타일 전체를 갱신 단위로 사용하며 `R + 64` 보정은 제거한다.

건축으로 바뀐 높이·나무·풀도 각 변경 타일의 구독자에게 전달한다. 집 원점이나 조작자 위치는 기준으로 사용하지 않는다. 조작자의 작업 결과는 직접 응답하며, 원거리 작업이 해당 타일의 구독을 뜻하지는 않는다.

본문을 WebSocket으로 보내거나 revision(대상별 상태 버전)을 알린 뒤 HTTP로 받는다. 어느 방식이든 수신자는 같은 타일 구독자다.

| 상태 | 갱신 시점 |
| --- | --- |
| 구독 중 새 revision 수신 | 필요한 HTTP 본문을 즉시 재요청. 이동까지 기다리지 않음 |
| 범위 밖 캐시를 가지고 재진입 | 서버 revision 확인 후 최신 본문으로 활성화 |
| 요청 실패 | 미동기화 상태를 유지하고 재시도 |
| 높이 변경 | 높이와 이에 의존하는 나무·풀 배치를 함께 갱신한 뒤 완료 처리 |

agent의 높이는 메모리와 HTTP 디스크 캐시 모두 갱신한다. 재진입 검증을 구현한 뒤 범위 밖 모든 접속자에게 보내던 무효화를 제거한다.

### 3.7 플레이어 상태와 효과

| 대상 | 전달 기준 |
| --- | --- |
| 장비·횃불·젖음·탑승·칭호·발광·상호작용 자세 | 플레이어 구독자 |
| 악기 시작·음표 | 연주자의 실제 위치·공간과 R. `INSTRUMENT_AUDIBLE_RADIUS` 제거 |
| 낚시 동작·찌·낚싯줄 | 하나의 세션으로 묶어 낚시하는 플레이어의 실제 위치·공간과 R 적용 |
| 투사체 등 독립적인 지속 효과 | 자체 위치·형상과 수명 |
| 즉시 끝나는 공격·피격 효과 | 각 효과의 위치·영역과 R |

낚시는 찌 좌표를 표시용으로 전달하되 찌의 이동으로 구독자를 바꾸지 않는다. 찌만 가깝고 플레이어는 R 밖인 관찰자가 효과를 받지 못하는 경우는 허용한다.

지속 효과는 중간 진입 시 현재 상태를 복원하고, 종료·이탈 시 기존 구독자의 표시·소리를 정리한다. 낚시하는 플레이어가 순간이동하거나 접속을 끊어도 기존 구독자에게 종료가 전달돼야 한다. 과거의 공격·음표는 재생하지 않는다.

효과가 범위 밖 엔티티를 참조하면 표현에 필요한 좌표·공개 정보만 포함하거나 효과를 분리한다. 참조 ID를 받았다는 이유로 그 엔티티를 활성 목록에 추가하지 않는다.

## 4. 상태 수명주기와 순서

| 이전 전송 목록 | 새 판정 | 전달 |
| --- | --- | --- |
| 없음 | 구독 대상 | 최신 전체 상태 `Enter` |
| 있음 | 구독 유지 | 변경 `Update` |
| 있음 | 범위 이탈 | `Leave` |
| 있음 | 월드에서 삭제 | `Delete` |
| 없음 | 구독 대상 아님 | 주변 전달 없음 |

`Leave`는 해당 시야에서의 해제, `Delete`는 월드에서의 삭제다. 몬스터 사망 후 남는 시체도 지속 상태다. 기존 `MonsterSpawned` 같은 메시지를 재사용하더라도 내부 의미는 구분한다.

### 4.1 갱신과 이동 순서

- 로그인·이동·순간이동·리스폰·층 전환 및 대상의 생성·이동·형상 변경 때 관심 집합을 갱신한다.
- 진입 스냅샷에는 현재 문 열림·수량·사망·연주 등 런타임 상태를 포함한다. 빈 목록도 적용해 이전 대상을 정리한다.
- 상태 확정, 관심 집합 등록, 스냅샷 큐 삽입을 묶고 그 뒤 변경을 순서대로 전달한다. 스냅샷에 포함된 revision을 중복 적용하지 않는다.
- 이탈·삭제 수신자는 이전에 그 대상을 받은 사용자다. 새 위치나 반경으로 정리 수신자를 다시 줄이지 않는다.
- 이동을 처음 받는 사용자는 `Enter → 이동`, 이탈하는 사용자는 `마지막 이동 → Leave` 순서로 받는다. 같은 구간이 스냅샷에 포함되면 합칠 수 있다. 웹은 마지막 구간의 화면 내 보간 후 표시를 정리한다.
- 이동 중에는 현재 확정 위치 또는 유효한 현재 구간 목표가 R 안이면 구독을 유지한다. 목표 변경·중단·보정·사망 때 다시 계산하며, 완료·취소된 구간으로 유지하지 않는다.
- 목표점 때문에 미리 받은 대상도 실제 현재 위치로 표시하고 LLM 인지에 포함한다. 목표점을 현재 위치나 공격 가능 거리로 사용하지 않는다.

### 4.2 버전과 복구

| 식별자 | 용도 |
| --- | --- |
| `world_epoch` | 서버 재시작 전후 캐시 구분 |
| 연결별 관심 집합 세대·송신 순번 | 과거 시야 응답과 누락 판별. 이전 구간의 늦은 `Leave`가 새 구독을 지우지 않게 함 |
| 대상별 `revision`과 삭제 표식 | HTTP·여러 agent 연결의 역순 응답, 삭제 후 이전 상태 복원 방지 |

전체 스냅샷에는 적용 범위와 완료 경계를 둔다. 임시 목록에 구성한 뒤 해당 연결의 시야에 적용한다. 큰 지형의 HTTP 응답은 서버가 알려준 revision과 일치할 때 활성화한다.

요청 실패를 빈 정상 상태로 처리하지 않는다. 재연결 시 시야를 비우고 새 스냅샷을 받으며, 스트림 누락이나 복구가 필요한 순서 불일치는 재동기화한다.

## 5. 구현 구조

### 5.1 서버의 공통 전달 계층

`server/src/game_state/interest.rs`에 공통 판정, 연결별 전송 목록, 대상별 구독자, 순서 있는 송신 큐를 둔다. 기능 코드는 상태·위치·형상을 제공하고 이 계층이 수신자를 결정한다. API 이름은 구현 시 조정할 수 있다.

```text
reconcile_view(player_id)
publish_subject_change(subject_id, change)
publish_movement(subject_id, from, to, movement)
publish_effect(effect_bounds, space, effect)
remove_subject(subject_id, final_revision)
send_to_participants(player_ids, result)
```

주변 전달 API는 반경 인자를 받지 않는다. `player_ids_within_position(..., radius)` 같은 조회는 공격·상호작용·AI 내부 판단에만 사용한다. `ServerMessage`는 §1의 분류를 명시하며 미분류 메시지를 자동 전역 전송하지 않는다.

집을 포함한 동적 객체는 WebSocket 스냅샷으로 전달한다. 어드민 REST 변경도 공통 계층을 거친다. 편집용 집 HTTP API는 유지할 수 있지만 그 응답을 일반 플레이의 활성 상태에 직접 적용하지 않는다.

### 5.2 웹과 agent-client의 상태·캐시

- 웹의 표시와 WASM 충돌은 같은 활성 동적 목록을 사용한다. 정적 배치 충돌 위에 해당 목록의 동적 충돌을 합친다. 모델·텍스처 캐시는 메모리 예산에 따라 재사용할 수 있다.
- agent의 연결별 `WorldView`는 활성 대상 ID·공간·동기화 상태를, `WorldCache`는 revision이 있는 공유 본문·정적 데이터를 가진다. 여러 연결의 본문은 대상 revision으로 병합하며 연결별 세대는 서로 비교하지 않는다.
- agent A가 떠나도 B가 사용하는 집 본문은 유지한다. 사용하는 활성 시야가 없어지면 공유 집 런타임 데이터도 해제한다. 다른 연결의 대상이 자신의 주변 목록에 포함되지 않게 한다.
- 집의 웹 `LOAD_RADIUS`·`EVICT_RADIUS`·청크 HTTP 요청과 agent의 `fetch_houses_around`·`fetched_house_chunks`를 제거한다.
- 정적 가구의 `fetch_furniture_around`·`fetched_furniture_regions`와 먼 스케줄 목적지의 정적 데이터 사전 로드는 유지한다. 버전 변경은 §1의 캐시 정책을 따른다.
- 장거리 경로는 잠정 경로로 두고 접근하면서 최신 동적 충돌로 다음 구간을 갱신한다. 스냅샷 대기 영역은 미확인 상태로 두며, 검증된 영역까지 이동한 뒤 갱신되면 이어간다. 서버 위치 보정을 우선 적용하고, 보정이 반복되면 재동기화해 경로를 다시 계산한다.

### 5.3 agent 인지

LLM 상태 목록·이벤트·대상 검색은 활성 `WorldView`를 사용한다. 이미 받은 동적 대상을 27 m나 현재 위치 중심의 원으로 다시 거르지 않는다. 발견 알림은 활성 대상의 진입·퇴장에 연결하고 ID·구독 세대로 중복을 억제한다. 기존 27 m 진입/`27 + 5 m` 망각 범위는 제거한다.

넓게 캐시한 정적 데이터의 주변 정보 선택과 지형 요약·시야 표시에는 공통 R을 사용한다. 거리·방향 표시, 정렬, 요약, 중복 이벤트 병합은 유지할 수 있다.

이관 범위는 [perception.rs](../agent-client/src/state/perception.rs), [world_state.rs](../agent-client/src/state/world_state.rs), [events.rs](../agent-client/src/state/events.rs)의 몬스터 이동 필터, [social.rs](../agent-client/src/state/social.rs)·[movement.rs](../agent-client/src/state/movement.rs)의 대상 검색, [prompt.rs](../agent-client/src/driver/prompt.rs)다.

## 6. 새 기능 구현 절차

1. **분류:** §1의 메시지 분류에 따라 전달 성격을 정한다.
2. **대상 정의:** §3에 따라 동기화 단위, 위치·형상·공간을 정한다. 이동은 패킷의 시작점·목표점을 명시한다.
3. **전달 연결:** §5.1의 공통 API를 사용한다. 기능 내부에 별도 반경이나 수신자 계산을 추가하지 않는다.
4. **수명주기:** 지속 상태에는 진입 스냅샷, 변경, 종료·삭제·이탈을 구현하고 §4의 순서·revision을 적용한다.
5. **클라이언트:** 웹 표시·충돌과 agent 상태·인지에 같은 진입·갱신·정리를 연결한다.
6. **검증:** §8에서 해당되는 경계·재진입·삭제·공유 캐시 시나리오를 검증한다.

## 7. 이관과 성능

### 7.1 구현 순서

| 단계 | 작업 |
| --- | --- |
| 1. 공통 기반 | shared 판정·WASM 상수 API, 관심 집합·송신 순서·버전, 메시지 분류 도입 |
| 2. 집 | 생성·수정·철거·문·창문을 집 구독으로 이관. 스크롤 건축·어드민 삭제 포함. `apply_open_door_state`가 반영된 스냅샷과 §5.2 캐시 구조 적용 |
| 3. 엔티티·효과 | 기존 AOI 대상, 이동 끝점 판정, 던전 문·소품, 악기·낚시를 §3~4로 이관. agent 인지는 §5.3 적용 |
| 4. 지형·기존 경로 제거 | 타일 revision·즉시 재수신·agent 디스크 캐시 갱신 완성 후 전역 무효화와 개별 주변 송신 경로 제거 |

### 7.2 기존 상수의 다른 용도

- `NPC_SIGHT_RADIUS`는 [deals.rs](../server/src/game_state/deals.rs)의 거래 제안 허용 거리와 [walk.rs](../agent-client/src/driver/walk.rs)의 이동 제한에도 쓰인다. 주변 대상 선택은 활성 시야로 옮기고 행위 제한은 별도 규칙으로 분리한 뒤, 상수·재노출·관련 assertion을 제거한다.
- `EVENT_DELIVERY_RADIUS`는 [monster_ai.rs](../server/src/game_state/monster_ai.rs)의 활성 AI 조회, [ambient_spawn.rs](../server/src/game_state/ambient_spawn.rs)의 스폰 제약, 몬스터 소유권, 던전 입구 조작 검사에도 쓰인다. 시야와 연동할 항목은 함께 검증하고 조작 거리 등은 용도에 맞게 분리한다.

### 7.3 성능과 배포

현재 [카메라 설정](../client/src/lib/components/game-scene/camera-utils.ts)의 기본 각도·평지·최소 일반 줌에서 32:9 화면 모서리는 약 39.6 m까지 보인다. 이 경우도 §1의 가장자리 정책을 따른다. 균일한 밀도에서 점 이벤트 수신자 수는 대략 R의 제곱에 비례한다. 32→64 m 확대 시 약 4배이며, 실제 부하는 대상 크기와 사용자 분포에 따라 측정한다.

- 기존 공간 인덱스를 활용하고, 움직인 관찰자·대상 주변만 갱신한다.
- 집·타일·울타리는 실제 영역이 걸친 셀에 등록하고 월드 순환을 처리한다.
- 본문은 한 번 직렬화해 공유한다. 경계 왕복 비용은 캐시·같은 틱 변경 병합으로 줄인다.
- 메시지별 수신자 수·송신량, 활성 대상 수, 스냅샷 크기·지연, 재동기화·역순 응답 폐기 수, 이동·AI 처리 시간을 이관 전후 비교한다.

[shared/src/lib.rs](../shared/src/lib.rs)의 정책에 따라 메시지 형태·의미가 바뀌면 `PROTOCOL_VERSION`을 올린다. 웹 WASM·서버·agent-client를 호환되는 버전으로 함께 배포 준비하고, 원격 agent와 포크에 변경을 안내한다. 롤백도 세 구성요소의 버전을 맞춘다. 위 단계는 개발·검토 단위이며 구형 클라이언트가 새 의미를 잘못 처리하는 중간 상태는 배포하지 않는다.

## 8. 검증 기준

검증은 shared 판정, 서버 수신자·수명주기, 웹·agent 상태 적용으로 나누고 같은 데이터로 확인한다. 거리 경계는 R에서 파생한다.

| 시나리오 | 기대 결과 |
| --- | --- |
| `R-ε`·`R`·`R+ε`, X 순환·음수 좌표 | 경계 포함과 진입·퇴장 판정 일치 |
| 다른 층·다른 던전의 같은 깊이 | 대상별 공간 정책 준수 |
| 조작자는 멀고 대상은 가까움 / 그 반대 | 대상의 구독 규칙으로 수신자 결정 |
| 집 원점은 멀지만 방은 가까움, 회전·청크 경계·같은 청크 안 이동 | 실제 바닥 영역으로 집 전체 구독·해제 |
| 집 위층에서 철거 관찰, 2층 창문을 지상·다른 주택층에서 관찰 | 집 구독자 모두 변경 수신. 다른 층 생물은 미공개 |
| 숨긴 상층 메시의 창문 변경 후 외관 표시 | 최신 상태 표시 |
| 문이 열린 상태로 이탈한 뒤 닫힘·복귀, 범위 밖 동적 대상 생성·수정·철거 | 최신 스냅샷과 충돌 적용. 삭제된 대상 잔존 없음 |
| 정적 가구 재방문 / 데이터 버전 변경 배포 | 같은 버전은 재사용, 변경 시 캐시·다운로드 기록·충돌 갱신 |
| 던전 입구 마커와 실제 문 위치가 다름, 자동 닫힘, 원거리에서 문·소품 변경 후 접근 | 실제 대상 위치 판정과 최신 상태 복원 |
| 관찰자 또는 몬스터 이동, 시작점만·목표점만·둘 다 R 안 | 등장 후 이동 전달. 수신자 중복 없음 |
| 현재 위치는 R 밖, 목표점은 R 안 | LLM 인지 포함. 실제 현재 위치와 목표 구별 |
| 두 끝점 모두 R 밖 | 끝점 OR 조건의 수신자는 아님. 기존 구독자의 종료·퇴장 정리는 전달 |
| 목표 변경·중단·보정·사망, 마지막 이동 후 이탈 | 이동·종료 갱신 뒤 퇴장. 이전 구간의 응답이 새 구독을 제거하지 않음 |
| 순간이동·집 위치 변경 직후 삭제 | 이전 구독자 정리와 새 구독자 스냅샷·삭제 순서 보장 |
| 늦은 HTTP·여러 agent 연결의 역순 응답·삭제 후 응답 | revision 역행·삭제 대상 복원 없음 |
| agent A 이탈, B는 집 사용 / A 재진입 | B 충돌 유지, A 최신 상태 복원, 시야 간 대상 혼입 없음 |
| 기존 27 m 밖의 대상·이벤트, 원거리 공유 캐시 | 동적 대상은 활성 시야 사용, 정적 주변 정보는 공통 R 적용 |
| 연주·낚시·모닥불·시체 중간 진입과 종료 | 현재 상태 복원과 종료·이탈 정리. 과거 일회성 효과 재생 없음 |
| 기존 30 m 밖에서 악기 관찰 | 시작·음표 수신과 종료 정리 |
| 낚시 플레이어만 가까움 / 찌만 가까움, 찌 이동·플레이어 순간이동·접속 해제 | 플레이어 기준 구독, 실제 찌 좌표 표시, 기존 구독자의 종료 정리 |
| 타일 중심은 멀지만 가장자리는 가까움 / 모서리에서도 R 밖 | 실제 타일 영역으로 구독 결정 |
| 조작자·집 원점은 멀지만 변경 타일은 가까움 | 해당 타일 구독자 갱신, 작업 결과는 조작자에게 응답 |
| 정지 관찰자의 타일 revision 수신 / 원거리 캐시로 재진입 | 즉시 재요청 / 활성화 전 revision 검증 |
| agent에 이전 높이 메모리·디스크 캐시가 남음, 갱신 요청 실패 | 최신 높이·종속 배치로 갱신. 실패 상태를 완료로 처리하지 않음 |
| 접속 해제·송신 누락·재시작·스냅샷 실패 | 재동기화 |
| 화면비·카메라 회전·고저차·일반 줌아웃 변경 | 32 m 정책 유지. 가장자리 현상 허용, 구독 진입 시 최신 상태 복원 |

완료 기준은 서버의 관심 집합과 웹·agent-client의 활성 상태가 일치하고, 재진입 시 최신 상태가 복원되는 것이다. 화면 전체 동기화는 요구하지 않는다.

이 문서는 설계와 검증 계획이며, 동작 코드 변경이나 실행 검증 결과를 포함하지 않는다.
